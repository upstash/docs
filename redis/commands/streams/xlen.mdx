---
title: "XLEN"
description: "Get stream length."
---

Use `XLEN` to get the number of entries currently in a stream.

Deleted and trimmed entries are not counted, and the reply is `0` when the key does not exist. The number reflects what is stored right now, not how many entries the stream has ever carried, so it is a measure of retained data rather than of throughput; a group's backlog is reported by the lag in [`XINFO GROUPS`](/redis/commands/streams/xinfo-groups).

## Syntax

```redis
XLEN <key>
```

## Arguments

| Argument | Required | Repeatable | Description |
| --- | --- | --- | --- |
| `<key>` | Yes | No | Redis key targeted by the command. |

## Response

The reply reports the result of the operation. Error replies have the same shape in RESP2 and RESP3 and are surfaced as exceptions by the SDKs below.

| Protocol | Reply |
| --- | --- |
| RESP2 | Integer |
| RESP3 | Integer |

<Note>
  Client libraries often decode bulk strings, maps, sets, and numeric strings into language-native values. The table describes the Redis wire reply.
</Note>

## Examples

TCP examples use the TLS `REDIS_URL` from the Upstash console. REST examples use `UPSTASH_REDIS_REST_URL` and `UPSTASH_REDIS_REST_TOKEN`.

<Tab title="go-redis">

```go
package main

import (
    "context"
    "fmt"
    "os"

    "github.com/redis/go-redis/v9"
)

func main() {
    opts, err := redis.ParseURL(os.Getenv("REDIS_URL"))
    if err != nil {
        panic(err)
    }
    client := redis.NewClient(opts)
    result, err := client.XLen(context.Background(), "my-key").Result()
    if err != nil {
        panic(err)
    }
    fmt.Println(result)
}
```

fn main() -> redis::RedisResult<()> {
