---
title: "ZREMRANGEBYRANK"
description: "Remove members by rank range."
---

Use `ZREMRANGEBYRANK` to remove the members of a sorted set that occupy a range of positions.

Ranks are zero-based from the lowest score and may be negative to count from the top, so `ZREMRANGEBYRANK key 0 -101` keeps only the hundred highest scoring members. The reply is the number of members removed, and the key is deleted when it becomes empty.

This is the standard way to cap a leaderboard or any ranking to a fixed size after inserting into it, in the same spirit as [`LTRIM`](/redis/commands/list/ltrim) for lists.

## Syntax

```redis
ZREMRANGEBYRANK <key> <start> <stop>
```

## Arguments

| Argument | Required | Repeatable | Description |
| --- | --- | --- | --- |
| `<key>` | Yes | No | Redis key targeted by the command. |
| `<start>` | Yes | No | Start index; negative values count from the end. |
| `<stop>` | Yes | No | Stop index, inclusive; negative values count from the end. |

## Response

The reply reports the result of the operation. Error replies have the same shape in RESP2 and RESP3 and are surfaced as exceptions by the SDKs below.

| Protocol | Reply |
| --- | --- |
| RESP2 | Integer |
| RESP3 | Integer |

<Note>
  Client libraries often decode bulk strings, maps, sets, and numeric strings into language-native values. The table describes the Redis wire reply.
</Note>

## Examples

TCP examples use the TLS `REDIS_URL` from the Upstash console. REST examples use `UPSTASH_REDIS_REST_URL` and `UPSTASH_REDIS_REST_TOKEN`.

<Tab title="go-redis">

```go
package main

import (
    "context"
    "fmt"
    "os"

    "github.com/redis/go-redis/v9"
)

func main() {
    opts, err := redis.ParseURL(os.Getenv("REDIS_URL"))
    if err != nil {
        panic(err)
    }
    client := redis.NewClient(opts)
    result, err := client.ZRemRangeByRank(context.Background(), "my-key", 0, 0).Result()
    if err != nil {
        panic(err)
    }
    fmt.Println(result)
}
```
