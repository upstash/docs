The Upstash Console exposes metrics in two places: the database list, and the detail page of a single database. This page explains what each chart shows.

## Database List

The list view aggregates summary information across all of your databases.

</Frame>

Click a database name to open its detail page. For each row the list shows:

- The region of the database
- The plan of the database (free, pay-as-you-go, fixed, or enterprise)

## Database Usage

The "Usage" tab of a database shows detailed charts. Pick the period at the top of the tab: the past hour, 3 hours, 12 hours, day, 3 days or week. Databases on a Pro plan or with the Production Pack can also select the past month. Charts refresh every minute.

### Top Commands

The ten most executed commands over the period, one line each.

### Throughput

## Insights

Databases on a Pro plan or with the Production Pack have an **Insights** tab next to Usage. It has two views.

### Metrics

One panel per signal, each with the current value, the change against the previous half of the period and the anomaly windows the console found. The chart highlights the largest anomaly with its peak against the typical value. Pick the period at the top, from the past hour to the past month.

- **Latency**: request time from arrival to response across all commands, as p50, p90 or p99.
- **Ops per second**: commands processed each second.
- **Engine time (p99)**: the time Redis itself spent executing the command.
- **Network and queueing (p99)**: the request time not spent in the engine, derived as total minus engine time, so a slow p99 can be placed inside Redis or on the way to it.
- **Lock wait (p99)**: the time commands waited for the execution lock, typically caused by large scripts or big-key commands.
- **Lua latency (p99)**: script execution time.
- **Disk load (p99)** and **Keys loaded from disk**: how long it took to fetch a key that was not in memory, and how often it happened in each ten-minute window.
- **Disk size**: the stored data size.

The **Server** selector narrows every panel to one replica. **Separate by region** draws one line per region of a global database next to the total, so a regional spike stands out. Latencies combine replicas by taking the highest value; throughput and disk loads add up.

Below the panels the tab lists limits and security events, slow commands and Lua scripts.

### Routing map

Where requests entered the proxies today and which replica served them, drawn on a world map. Entry regions and serving replicas are marked, each route is a line whose width follows its request count, and the list next to the map has every route with its share of today's requests, whether it was served locally, in the same region or cross-region, and its error count. Counts reset at midnight. A large cross-region share means a read region close to your clients would remove a network round trip from every request.

Under the map, the same view shows the client networks of the last hour, masked to /24 and attributed to a cloud provider and region when the address belongs to a published AWS, Google Cloud or Cloudflare range, and today's requests by SDK, platform and runtime with the share that needed a retry.

### Limits and Security

Requests rejected today for exceeding the request or record size limit and commands throttled today, next to the limits of your plan; failed authentications, connections opened and keyspace notifications over the selected period; clients currently running MONITOR; bandwidth today by direction; the live data size against the monthly average; the ACL users that signed in today with their login counts; and the limits the database hit recently.

### Slow Commands

Commands that took longer than 500 milliseconds to execute today, with how often it happened and the slowest run. Only command names are recorded, not keys or arguments.

### Lua Scripts

The script latency as p50 and p99, and a table of the most executed scripts today: executions, commands they ran, failures including timeouts and memory-limit hits, average and slowest duration, the share of time spent in Lua versus in Redis commands, and memory use.

## Backup Insights

On the Backups tab, a completed backup of a Pro or Production Pack database has an **Analyze** action. It scans the backup offline, without touching the running database, and reports the number of keys, elements and bytes, the distribution of key sizes and element counts per type, the biggest keys overall and per type with their expiry, and an expiration profile that shows how much data is persistent, already expired but not yet removed, or about to expire. Once the report is ready the action turns into **Insights**.
