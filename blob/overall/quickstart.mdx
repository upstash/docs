Upstash Blob is S3-compatible object storage. Each server SDK has a bucket client and an upload handler, and `@upstash/blob` has React hooks that upload from the browser straight to storage. This page builds a working file picker in React. The server code is Next.js App Router in TypeScript, or FastAPI in Python. Other frameworks work the same way; see [Other frameworks](/blob/sdks/ts/upload-handler#other-frameworks) in TypeScript and [Mounting it](/blob/sdks/py/upload-handler#mounting-it) in Python.

---

## Setup

<CodeGroup>
```bash npm
npm install @upstash/blob
```

```bash pnpm
pnpm add @upstash/blob
```

```bash yarn
yarn add @upstash/blob
```

```bash bun
bun add @upstash/blob
```

```bash pip
pip install upstash-blob
```

```bash uv
uv add upstash-blob
```
</CodeGroup>

`upstash-blob` is the Python server SDK. The browser side is `@upstash/blob` whichever language runs the server, so a Python app installs both.

Create a bucket in the [Upstash Console](https://console.upstash.com) and put its token in your environment.

```bash .env
UPSTASH_BLOB_TOKEN=...
```

The console asks whether the bucket is public or private:

- **Public**: every object has a public URL. For avatars, product images, anything a page links to directly.
- **Private**: no public URL. Every read goes through a time-limited [signed URL](/blob/bucket/reading#signed-read-urls). For user documents, invoices, anything that must not be guessable.

## Upload from your server

<CodeGroup>
```ts TypeScript
// lib/reports.ts
import { Bucket } from "@upstash/blob"

const bucket = Bucket.fromEnv()

export async function saveReport(file: Blob) {
  const blob = await bucket.put("reports/2026-01.pdf", file, {
    contentType: "application/pdf",
  })
  return blob.url
}
```

```python Python
# app/reports.py
from pathlib import Path

from upstash_blob import Bucket

bucket = Bucket.from_env()


def save_report(pdf: Path) -> str | None:
    blob = bucket.put("reports/2026-01.pdf", pdf, content_type="application/pdf")
    return blob.url
```
</CodeGroup>

Bytes already on your server go to the bucket with `put`. The returned record's URL is the public object URL, not set on a private bucket. See [Writing](/blob/bucket/writing), and the [TypeScript SDK](/blob/sdks/ts/overview) or [Python SDK](/blob/sdks/py/overview) for setup details.

## Upload from the browser

Files a user picks go straight from the browser to storage. Your server only authorizes the upload and records the result, so the bytes never pass through it.

<Steps>

<Step title="Write the upload handler">

<CodeGroup>
```ts TypeScript
// lib/uploads.ts
import "server-only"
import { uploadHandler } from "@upstash/blob"

export const uploads = uploadHandler({
  constraints: {
    maxSize: "20mb",
    contentTypes: ["image/*", "application/pdf"],
  },

  onBeforeUpload: ({ file }) => ({ path: `images/${file.name}` }),
})
```

```python Python
# app/uploads.py
from upstash_blob import AsyncUploadHandler, BeforeUploadResult

uploads = AsyncUploadHandler(
    max_size="20mb",
    content_types=["image/*", "application/pdf"],
    on_before_upload=lambda args: BeforeUploadResult(path=f"images/{args.file.name}"),
)
```
</CodeGroup>

The handler runs on your server. It decides who may upload, where the object goes, and what happens once it lands. It never sees the bytes.

This one accepts anyone. [Upload handler](/blob/uploads/upload-handler) adds the auth check and the completion callback.

</Step>

<Step title="Mount it as a route">

<CodeGroup>
```ts TypeScript
// app/api/upload/route.ts
import { uploads } from "@/lib/uploads"

export const { GET, POST } = uploads
```

```python Python
# app/main.py (FastAPI)
from fastapi import FastAPI
from upstash_blob.fastapi import upload_view

from app.uploads import uploads

app = FastAPI()
app.add_api_route("/api/upload", upload_view(uploads), methods=["GET", "POST"])
```
</CodeGroup>

`POST` runs the upload and `GET` serves the route's constraints. The hooks look at `/api/upload` by default, so nothing else has to name a URL.

</Step>

<Step title="Bind the hooks to the handler">

```ts lib/upload-hooks.ts
"use client"

import { uploadHooks } from "@upstash/blob/react"
import type { uploads } from "./uploads"

export const { useUpload } = uploadHooks<typeof uploads>()
```

`uploadHooks<typeof uploads>()` reads the handler's type, so route names and completion data are checked at compile time. The `import type` is erased at build time and never pulls server code into the browser bundle.

A Python handler has no type to bind to. Call `uploadHooks()` with no type parameter and pass the URL, `useUpload("/api/upload")`, in the next step. [FastAPI + React](/blob/recipes/fastapi-react) has the whole app, including the dev proxy that puts `/api` on the page's origin.

</Step>

<Step title="Upload a file">

```tsx app/page.tsx
"use client"

import { useUpload } from "@/lib/upload-hooks"

export default function Page() {
  const { start, upload, accept } = useUpload()

  return (
    <div>
      <input
        type="file"
        accept={accept}
        onChange={(e) => start({ file: e.target.files?.[0] })}
      />

      {upload && <p>{upload.status}</p>}
      {upload?.pending && <progress value={upload.percent} max={100} />}
      {upload?.status === "done" && (
        <a href={upload.blob.url}>{upload.blob.path}</a>
      )}
      {upload?.status === "error" && <p>{upload.error.message}</p>}
    </div>
  )
}
```

</Step>

</Steps>

You get these without more code:

- **Multipart for large files.** Past 16 MB the SDK switches to parts, with pause, resume and per-part retry. See [Large files](/blob/uploads/large-files).
- **Retries.** Failed parts back off and retry, and an expired signature is refreshed mid-upload.
- **A picker that matches the server.** `accept` comes from the route's own `GET`, so an oversized file is refused before any request goes out. See [Constraints](/blob/uploads/constraints).
- **Progress.** `percent`, `status` and `pending` read the same for one PUT or 200 parts.
- **Types end to end.** With a TypeScript handler, whatever `onUploadComplete` returns is `upload.blob.data` on the client, typed.
